試合を登録してスコアブックを付けるまでの流れと、試合詳細（ボックススコア）の読み方をまとめます。記録した打席から成績がどう導かれるかは [試合がすべての出典](試合がすべての出典) を参照してください。

## スコアブックの付け方

試合の記録は、どちらかのチームの担当者（または管理ユーザー）がログインして行います（[チームと選手の管理](チームと選手の管理#チーム担当者)）。

1. **試合を登録する**: 試合一覧の「試合を登録」（`/games/new/`）を開き、シーズン・試合日・ホームとビジターのチームを入れて登録します。
   得点は入れません。登録しただけの試合は「未記録」と表示され、順位や成績にはまだ数えられません
2. **編集画面を開く**: 試合詳細の「記録を編集」から、スコアブックの編集画面（`/games/<id>/edit/`）に移ります
3. **ラインアップを書く**: 「ラインアップ」カードで、両チームの打順1〜9に選手と守備位置を選びます。
   選べるのは**その試合の年に支配下の選手**だけです（育成選手は試合に出られません。保存でも拒否され、昇格した年の試合なら出られます。
   [支配下と育成](チームと選手の管理#支配下と育成)）。
   途中出場の選手は、その打順の「交代を追加」で行を足します。守備固めのように守備から入った選手だけ、
   「出場した半回」に何回の表／裏の何人目の打者から出場したかを入れます（代打・代走・投手は打席から自動で決まります）
4. **打席を1つずつ記録する**: 「スコアブック」カードの「次の打席を記録する」を押すと、次の打者の入力パネルが開きます。
   - 「結果」を選ぶと、走者の進塁が既定値で埋まります。既定と違うときだけ「走者の動き」を直します
     （塁に残ったままの走者は「〜の走者を動かす」で動かせます）
   - 「投手」を選び、アウトになった打球は「打球の処理」に守備の経路を書きます（例: `遊-一`）。
     刺殺・補殺はこの経路から数えられます
   - 失策が絡む結果では、失策した守備者と失策の種類を選びます
   - 「この打席を記録する」で確定します。アウトが3つになると次の半回に進みます
5. **間違えたら直す**: マス目の打席を押すとその打席を直せます（「この打席を直す」）。直近の打席は「最後の打席を取り消す」で消せます
6. **検算を見て保存する**: 「導出値の確認」カードでイニングスコアと、打点の合計が得点を超えていないかを確かめ、「保存する」を押します。
   得点・勝敗・セーブ・ホールド・成績は保存した打席から自動で導かれます。記録に矛盾があると、画面上部にエラーが出て保存されません

## 編集画面のつくり

画面は4つのカードでできています。

| カード | 内容 |
| --- | --- |
| 試合の情報 | シーズン・試合日と、**打席から導いた得点の表示**（入力欄ではありません） |
| ラインアップ | 両チームの打順1〜9をロスターから選ぶ |
| スコアブック | 打順9行 × イニング列のマス目と、打席の入力パネル |
| 導出値の確認 | イニングスコアと検算（打点の合計が得点を超えていないか） |

- **入力は順番に積みます。** 打席の通し番号は1から欠けずに続き、打順は1〜9を巡回するという
  決まりがあるので、任意のマスに後から差し込む形にはしていません。マス目は記録済みの打席を
  読むためのもので、クリックするとその打席を直せます
- **結果を選んだ時点で走者の進塁が既定値で埋まります**（単打なら走者は1つ進む、四球なら
  埋まっている塁だけ押し出し、など）。既定と違うときだけ触ります。素朴に作ると1打席あたり
  3〜5操作になるところを、大半の打席は「結果を選ぶだけ」で終わります
- **打席の語彙（結果・進塁の理由・塁・失策の種類）と既定の進塁の対応表は payload に載せます。**
  TypeScript から Python の Enum は読めないので、画面側に同じ表を書くとずれても例外にならず、
  選択肢や既定値だけが静かに古くなります。払い出せば出典は1つのままです。
  TypeScript に残る重複は塁の番号だけで、
  [tests/integration/test_stat_fields.py](https://github.com/sumika157/baseball-league-manager/blob/main/myapp/tests/integration/test_stat_fields.py) が
  ドメインの `Base` と突き合わせます
- React 側の塁の再生・既定の進塁・検算はすべて入力補助で、確定判断は常にサーバーが持ちます

## ボックススコア

試合詳細はスコアブックと同じ形で並べます。**打順・守備位置・継投を記録するので、
スタメンと途中出場が区別できます。**

| 区分 | 内容 |
| --- | --- |
| スコアボード | 回ごとの得点（延長も可）と、計・安・失 |
| スコアブック | 打順 × 回のマス目に打席の結果を並べた読み取り専用の表（編集画面と同じ並び。打者一巡で同じ回に2打席立てば1マスに縦に並ぶ） |
| 打撃 | 打順 → 位置 → 選手名 → 打率・打数・得点・安打・打点・本塁打・二塁打・三塁打・四球・死球・三振・犠打・犠飛・盗塁・併殺打 |
| 投球 | 投げた順に、防御率・投球回・被安打・被本塁打・奪三振・与四球・与死球・失点・自責点・記録 |
| 守備 | 両チームごとに、守備に就いた野手と投手の位置・刺殺・補殺・失策（打席の記録が無い試合では出さない） |

- **安打・失策は打席から数えます**（`hits_by_inning` / `errors_by_inning`）。失策は
  **守備側のチーム**に付きます（表の打席の失策はホーム、裏の打席の失策はビジター）。
  打席の記録が無い古い試合は、安打を打撃明細の合計から出し、失策は「—」にします
- スコアブックの結果の表記は `PlateAppearanceResult.label` が出典です
  （画面ごとに別の略記表を持ちません）
- 打順は **打順（1〜9）と、その打順の何番目か**で表します。「スタメンか」は
  別に旗を持たず、打順の先頭（0番目）かで判断します。旗を持つと
  「交代なのにスタメン」という食い違いが起こりうるためです
- 同じ打順の交代選手は打順を繰り返さず、一段下げて示します
- 守備位置は試合で就いた位置（`投捕一二三遊左中右指`）。代打は「打」、代走は「走」です。
  **選手の登録位置（投手・捕手・内野手・外野手・指名打者）とは別の概念**で、
  登録は「主にどこを守るか」、こちらは「この試合でどこを守ったか」を表します
- 打率・防御率は**通算の値**を並べます。1試合ぶんの率は標本が小さすぎて
  読めないためです（0.1回1失点で防御率27.00になってしまいます）
