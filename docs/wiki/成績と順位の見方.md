成績一覧・個人ページ・順位表に並ぶ指標の意味と、勝敗・セーブ・ホールド・守備成績・順位がどう決まるかをまとめます。

## 指標

率（打率・OPS・防御率）は**合算した実数から計算し直します**。試合ごとや月ごとの率を
平均しても正しい率にはならないためです。

| 指標 | 内容 |
| --- | --- |
| 打率・出塁率・長打率・OPS | 打撃の基本 |
| **IsoP** | 長打率 − 打率。単打を差し引き、長打力だけを取り出す |
| 防御率・WHIP・K/9・BB/9 | 投球の基本。BB/9 の分子は四球だけ（死球は含めない） |
| **FIP** | 本塁打・四死球・奪三振だけで投球内容を測る。守備に左右されない |
| **OPS+ / ERA+** | リーグ平均を100とした指数 |
| **HP** | ホールド ＋ 救援勝利。救援投手の働きを表す |

**FIP・OPS+・ERA+ はリーグ全体の成績が無いと確定しません。**
1人ぶんの記録だけでは基準が決まらないため、リーグを知るアプリケーション層が
基準値（`_LeagueContext`）をまとめて求め、ドメインの計算に渡します。

- FIP はリーグの防御率と素点の差を定数として足し、防御率と同じ尺度で読めるようにします。
  リーグごとに定数が変わるのは、本塁打の出やすさや球場が違えば同じ内容の投球でも
  失点が変わるためです
- **ERA+ は防御率と向きが逆**（大きいほど良い）です。指数はどの指標でも
  「大きいほど良い」に揃えたいため、比率を反転させています
- 自責点0の ERA+ は比率が無限大になるので、`ERA_PLUS_CAP`（300）で頭打ちにします
- 未出場・未登板の選手は 0 とします。0打席・0回に指標を与えると実力と無関係な値になるためです

OPS+ は OPS と、ERA+ は防御率と順序が一致する（同じリーグなら基準が共通）ため、
**この2列に並べ替えは付けていません**。既存の OPS・防御率の列で同じ順序が得られます。

## 投球回（InningsPitched）

野球では `5.2` が **5回と2/3**（＝17アウト）を意味し、10進数の 5.2 ではありません。
この変換ルールは `InningsPitched` 値オブジェクトが唯一の出典で、内部では常に
アウト数の整数で保持します。`5.3` のような存在しない表記は `6.0` に正規化されます。

## 勝敗・セーブ・ホールド

**入力しません。イニングスコアと継投から、日本プロ野球の規則で導出します。**
規則から一意に決まるものを手入力させると、「勝利投手が2人いる」「負けチームの
投手に勝利が付く」といった食い違いが起こります。

| 記録 | 条件 |
| --- | --- |
| 勝利 | 勝ちチームが最後にリードを奪った時点の投手。**先発は5回以上**投げていないと付かず、最も内容の良い救援に回る |
| 敗戦 | その決勝点を許した投手 |
| セーブ | 試合を締めた投手で、**3点差以内のリードで登板して1回以上**、または**3回以上**を投げ、リードを保って終えた場合。完投と勝利投手には付かない |
| ホールド | セーブの条件を満たす状況で登板し、1つ以上アウトを取って**リードを保ったまま次の投手に引き継いだ**場合 |
| HP | ホールド ＋ 救援勝利 |

- どの条件も「継投した時点のスコア」を見るため、**回ごとの得点（イニングスコア）**が
  必要です。最終得点だけでは判定できません
- 判定は [domain/services/decisions.py](https://github.com/sumika157/baseball-league-manager/blob/main/myapp/domain/services/decisions.py) の `pitching_decisions()` に
  あり、DB を使わずに単体テストできます。手動入力と仮想データの投入で
  **同じ関数**を使うので、2つの実装がずれることがありません
- イニングスコアが未記録の試合では判定できないため、何も付けません
- 先発登板数と救援勝利はテーブルに持たず、**登板順から導きます**
  （登板順1なら先発、2以上での勝利が救援勝利）

## 守備成績

**刺殺・補殺・併殺参加は、打席の「打球の処理経路」から導きます**（失策だけは失策の記録から）。
入力するのは経路（6-3 なら遊→一）だけで、数えるのは `FieldingLine` と
[domain/services/scoring.py](https://github.com/sumika157/baseball-league-manager/blob/main/myapp/domain/services/scoring.py) の `fielding_lines_for()` です。

| 場面 | 付くもの |
| --- | --- |
| 6-3（遊ゴロ） | 遊に補殺、一に刺殺。最後の位置が刺殺、手前の各位置が補殺 |
| 8（中飛） | 中に刺殺だけ |
| 6-4-3 の併殺 | 遊に補殺、二に刺殺＋補殺、一に刺殺。**併殺は刺殺が2つ**（最後の位置と最後から2番目の位置。単独の併殺 "3" は同じ位置に2つ）。関わった全員に併殺参加が1つ |
| 三振で経路が空 | 捕手の刺殺（公認野球規則。入力させずに導く） |
| 野選出塁 | 走者を封殺した経路に刺殺・補殺 |
| 安打・四死球・本塁打・失策出塁 | 経路があっても付けない |

- **誰に付けるかは、その打席の時点で守備位置に就いている選手**です。ラインアップの各行が持つ
  **チーム**（`team_id`）と**出場した打席**（`entered_sequence`。スタメンは試合開始から）から引き、
  投手の位置はその打席の投手、代打・代走・指名打者は守備に就きません。同じ打順の枠では、
  次の選手が入る打席の手前まで前任者が守っています。
  - 出場した打席は、**代打は初めて打席に立った打席、代走は代走を出した打席**から導きます。
    **守備に就く途中出場（守備固めなど）だけ、「何回の表／裏の、その半回の何人目の打者から出場したか」を入力します**
    （その半回の n 人目の打席に読み替えます。入力が無い新しい記録は保存できません）。**投手は初めて投げた打席から導き**、代打・代走専用の行は入力を無視して打席から導きます（保存のたびに変わらないように）。代打からそのまま守備に就いた選手は、その代打の打席を指します
  - **途中出場で出場した打席が不明なら、その選手もその枠の前任者も解決しません**（推測しない）。
    同じ時点で同じ位置に2人いる場合も解決せず、付けずに飛ばします（例外にしない）
  - 失策の守備者が、その位置に就いている選手と食い違う記録は保存できません
  - **交代を伴わない守備位置の入れ替え**（同じ選手が試合中に別の位置へ移る）は、1行1位置では表せません
  - **三重殺・挟殺を含む経路**の刺殺は正確ではありません
  - 仮想データは代打の後の守備位置が空くため、7回以降の刺殺・補殺が低く出ます（打球方向を散らすのと同じく、後のシミュレーションエンジンで作り直します）
- 通算成績の集計のために `GameFieldingLine` として保存しますが、出典は打席です。
  打撃・投球の明細と同じく、**保存の前に集約が打席から導き直した値と照合します**（打席があるのに守備成績が空の集約も弾きます）
- 守備に就いた選手は守備機会が無くても行があります（守備の試合数を数えるため）
- 既存の試合の守備行は、マイグレーションでは作りません。**migrate の後に `docker compose exec web python manage.py rebuild_fielding_lines` を明示的に流します**（何度流しても同じ結果）。ラインアップのチームと出場した打席は `0035` が入れます（代打は初打席、代走は代走の打席、投手は初めて投げた打席。それ以外の途中出場は不明のまま。チームが決まらない・在籍の記録と食い違う行があれば止まります）
- 仮想データの経路は結果ごとに固定です（ゴロは遊→一、飛球は中、ライナーは三）。そのため
  二塁・左右翼に刺殺・補殺が付かず、遊・一・中に偏ります。打球方向を散らすのは後の課題です

## 順位

**順位は保持せず、勝率の高い順で自動的に決まります。** 手入力できるようにすると
勝敗と矛盾しても検知できないためです。

- 勝率は日本プロ野球の規則にならい **勝 ÷ (勝 + 敗)**。引分は分母に含めません
- 勝率が同じチームは同順位として扱います
- ゲーム差は首位との差を `((首位の勝 - 勝) + (敗 - 首位の敗)) ÷ 2` で算出します
- その年の成績が未登録のチームは順位表に載せません
  （0勝0敗として並べると、未登録なのか全敗なのか区別できなくなるため）。
  **未記録の試合**（登録しただけ）は1試合として数えません。未記録の試合しか無いチーム・
  シーズンも載りません

## タイトル

タイトル一覧には、NPB のタイトルのうち**成績だけで決まる12部門**を、シーズンごとに
**各部門の上位3人まで**出します。投票や選考で決まる賞（MVP・新人王・ベストナイン・
ゴールデングラブ・沢村賞）は成績からは決まらないので出しません。

| 部門 | 基準 | 対象 |
| --- | --- | --- |
| 首位打者 | 打率 | 規定打席以上 |
| 本塁打王 | 本塁打 | — |
| 打点王 | 打点 | — |
| 最多安打 | 安打 | — |
| 盗塁王 | 盗塁 | — |
| 最高出塁率 | 出塁率 | 規定打席以上 |
| 最優秀防御率 | 防御率 | 規定投球回以上 |
| 最多勝利 | 勝利 | — |
| 最高勝率 | 勝率（勝 ÷ (勝 + 敗)） | 13勝以上 |
| 最多奪三振 | 奪三振 | — |
| 最多セーブ | セーブ | — |
| 最優秀中継ぎ投手 | HP（ホールド＋救援勝利） | — |

- 率の部門は、1打席1安打で打率10割のような選手が首位に立たないよう対象を絞ります。
  最高勝率は NPB の規則どおり規定投球回ではなく**勝利数**で絞るので、救援投手でも13勝すれば対象です
- 本数そのものが記録になる部門は規定を設けず、0の選手は載せません
- 打撃部門に投手は入れません
- 同じ値の選手は同順位です（1・1・3 のように次の順位は飛びます）。3人で切るので、
  3位が並んだときは名前順で先の選手だけが載ります

## 規定到達での絞り込み（成績一覧）

成績一覧では**規定に到達した選手だけに絞れます**。率の指標（打率・防御率・OPS）は
規定未満の選手が混ざると読めません（1打数1安打が打率10割で並ぶため）。

- 規定打席 ＝ チームの試合数 × 3.1、規定投球回 ＝ チームの試合数 × 1.0（NPB の規則）。
  試合数に**未記録の試合は入れません**（登録しただけの試合で基準が上がり、規定に届く選手が
  いなくなるのを防ぐため）
- 条件は**タイトル一覧と同じドメインサービス**（`qualified_batters` /
  `qualified_pitchers`）が持ちます。画面側に別の条件を書くと、タイトルの対象と
  一覧の対象がずれます
- 切り替えの前に規模が分かるよう、**どちらの状態でも両方の人数**を出します
  （「全員 104 / 規定打席到達 54」）
- 野手／投手の切替と列の並べ替えとは互いに独立で、片方を押しても他方の指定は
  外れません。不正な指定はエラーにせず「全員」に落とします
